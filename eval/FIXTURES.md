# Fixtures — what exists, what it proves, how to run it

Every evaluation fixture in this repo, the exact command that builds or runs it, and — the part that
matters most — **what each one is not evidence for**.

All paths below are written as code spans rather than links because most fixture *data* is
git-ignored (regenerable, or third-party and non-redistributable). A fresh clone has the label layer
and the builders; it does not have the pixels.

> **Read the layer split before quoting any number from here.**
> Capability is deterministic and belongs in unit tests. Quality is statistical and belongs in an
> end-to-end benchmark at release. A fixture from the first group can never answer a question from
> the second.

| layer | fixture | on disk? | needs a key? |
|---|---|---|---|
| L0 capability | `eval/synthetic/` | ✅ regenerable | no |
| L1 quality | `eval/stage-validation/corpus.v1.1.json` | ✅ 100 cases | judge arms only |
| L1 audio | `eval/stage-validation/audio_corpus.json` | ✅ 53 cases | no |
| L2 temporal | `eval/stage-validation/long_sources/` | ✅ 7 sources | judge arms only |
| L3 long-horizon | `eval/longhorizon/sources/inject_2h_v1.mp4` | ✅ 120 min | judge arms only |
| L4 trust | `eval/fixtures-golden/` | ⚠️ labels only, mostly unreviewed | judge arms only |
| bench | `eval/golden-v1/` + `eval/bench-staging/` | ✅ 25 GB | judge arms only |

## L0 — synthetic capability corpora

**7 corpora, 22 cases.** Deterministic, scripted-judge-drivable, no API key, no spend, no footage.

```bash
# regenerate (safe, idempotent — the directory is git-ignored and marked GENERATED)
PYTHONPATH=packages/percept-vision python3 -m percept.harness.synthetic.generate
```

```python
from percept.harness.synthetic import load_corpus, load_all, ScriptedJudge
corpus = load_corpus("continuation")
case = corpus.case("same_subject_after_gap_is_two_episodes")
judge = ScriptedJudge.from_steps(case.steps)
case.expect["episode_count"]      # -> 2
```

| corpus | cases | pins |
|---|---|---|
| `subject_identity` | 3 | identity from a durable content key, incl. the honest `unknown` |
| `continuation` | 4 | continuation vs new episode across a 30 s gap |
| `mutation` | 3 | containing a value ≠ setting it; retraction; authority |
| `episode_counting` | 5 | count over episodes not frames; the `>=` boundary rule |
| `intervals` | 3 | coverage from observation, never interpolation |
| `idempotency` | 2 | one happening, one incident |
| `longhorizon` | 2 | subject recurs at min 2/7/14; bounded episode log |

**Verified determinism:** three consecutive regenerations produce byte-identical output.

> ⚠️ **A checked-out copy can be stale.** Regenerating on 2026-07-31 changed the on-disk corpus —
> it had been generated by an older generator and was missing a `longhorizon` case. The
> "byte-identical" guarantee holds *for a given generator version*, not across versions. **Regenerate
> before trusting a local copy**; it costs a second.

**Proves:** the mechanism can express the right answer.
**Never proves:** that a real model would produce that answer. Every verdict here is scripted.

## L1 — the derived quality corpus

**100 cases · 5 datasets × 20 · 2.98 hours · median clip 48.4 s · max 360.2 s.** Real footage, real
judge, bounded spend.

```bash
# rebuild the corpus manifest from eval/bench-staging/ (no spend)
PYTHONPATH=packages/percept-vision:. python3 eval/stage-validation/build_corpus.py
```

Case schema: `case_id`, `dataset`, `video_path`, `video_sha256`, `duration_s`, `goal_text`,
`goal_kind`, `positives`, `provenance`.

> ⚠️ **Two versions exist, and only one is in a fresh clone.** `corpus.v1.1.json` is **tracked**;
> `corpus.json` (v1.0) is **git-ignored**. So v1.1 is the only one you can build against after a
> clone, and it should be the default for new tooling.
>
> v1.1 carries 12 goal-text fixes — it stops pasting raw dataset tokens into the judged sentence
> (`"a person completes a jump_jack"` → `"a person completes a jumping jack"`).
> `corpus.version-diff.json` records every change and confirms case membership, media pins and
> ground truth are **identical** between them, so no offset or label depends on the choice.
> **State which version produced any number you quote.**

### Stage-validation runners

Per-stage recall/precision/economy. SV-1/2/4 run against the repo checkout; **SV-0 and SV-3 refuse
to** and require the installed wheel.

```bash
# SV-1 admission, SV-2 senses, SV-4 cognition — repo checkout, offline
PYTHONPATH=packages/percept-vision:. PERCEPT_MODE=offline python3 eval/stage-validation/sv1_admission.py
PYTHONPATH=packages/percept-vision:. PERCEPT_MODE=offline python3 eval/stage-validation/sv2_senses.py --quick
PYTHONPATH=packages/percept-vision:. PERCEPT_MODE=offline python3 eval/stage-validation/sv4_cognition.py

# SV-0 ingest, SV-3 pool — MUST run against the INSTALLED WHEEL. Omit PYTHONPATH.
PERCEPT_MODE=offline python3 eval/stage-validation/sv0_ingest.py
PERCEPT_MODE=offline python3 eval/stage-validation/sv3_pool.py
```

Putting `packages/percept-vision` on `sys.path` for SV-0/SV-3 gets you an explicit refusal, not a
silent wrong answer:

```
REFUSING TO RUN: percept resolved to the repo checkout …, not the installed launch wheel.
```

> ⚠️ **SV-0/SV-3 measure the installed wheel, which may not be your working tree.** The wheel
> currently resolves to `percept 0.8.3` in site-packages. Reinstall before reading these as a
> statement about your branch.

> ⚠️ **The SV runners write to `eval/stage-validation/results/`, which is TRACKED, and they do not
> short-circuit on `--help`.** Running one to "just see the options" overwrites a stored result file.
> This was discovered by doing it: `sv0_ingest.py --help` replaced `results/sv0_ingest.json` and
> destroyed 2,928 lines of stored output. Read `argparse` in the file, or run on a scratch branch, and
> `git status eval/stage-validation/results/` afterwards.

## L1 — the audio corpus

**53 cases · 0.472 h (28.3 min) · median 28.1 s · 179 positive intervals.** Ground truth derived from
SOUND, which the video corpus cannot supply — its largest dataset has no audio stream at all.

```bash
PERCEPT_MODE=offline PYTHONPATH=packages/percept-vision:. \
  python3 eval/stage-validation/build_audio_corpus.py \
    --out eval/stage-validation/audio_corpus.json
```

Takes ~2 min (ffprobe + sha256 over 53 files). No network. Defaults `--pt 40 --omnipro 10
--charades 10`; `--no-hash` skips hashing.

> **`--out` has no default.** Without it the script prints a summary and writes nothing — deliberate,
> because both consumers (`sv_audio.py`, `stage_metrics.py`) build the corpus **in-process** so no
> stale file can drift from what was measured. The filename above is a convention, not something the
> code looks for.

Three GT-strength tiers, **never averaged**:

| dataset | cases | `gt_strength` | usable as a bar? |
|---|---|---|---|
| `perception_test_sound` | 40 | `audio_annotated` (interval) | yes, with the caveat below |
| `omnipro_audio` | 3 | `audio_annotated_point` | **no — anecdote** |
| `charades_audible` | 10 | `proxy` (visual interval, audible label) | never |

Verified: 53/53 media paths exist; 53/53 `video_sha256` recomputed independently with `openssl` and
byte-exact; rebuild is byte-identical and matches the in-process build in `results/sv_audio.json`;
53/53 have an audio stream.

**Two things that bound what this corpus can support:**

1. **The 40-case `audio_annotated` bar is label-concentrated** — only 7 distinct goal texts, and
   `Interaction:hitting` is **24/40 (60%)**. A recall number off it is largely a number about impact
   sounds.
2. **The `omnipro_audio` tier is 3 cases and only 1 is a pure-audio trigger**; 2 of 3 carry OmniPro's
   own `audio_dependency: "none"`, i.e. the dataset says audio isn't needed. Not a build defect — only
   19 of 245 omnipro ids are fetched locally. Do not treat it as a tier.

Coverage is also narrow: 40 of 691 locally-usable Perception Test videos, out of 5,359 annotated. And
the "proactiveqa and repcount have no audio" refusals are **8-file samples**, not exhaustive.

## L2 — concatenated long sources

**7 built sources.** N clips sharing a goal, concatenated into ONE source bound to ONE watch, so a
goal that fires once per clip must fire N times with N−1 re-arms.

```bash
PYTHONPATH=packages/percept-vision:. python3 eval/stage-validation/build_long_sources.py   # per-goal
PYTHONPATH=packages/percept-vision:. python3 eval/stage-validation/build_long_run.py       # one joint source
```

| source | duration | occurrences |
|---|---|---|
| `perception_test__showing_something_to_the_camera` | 3.8 min | 9 |
| `repcount__situp` | 2.8 min | 5 |
| `repcount__frontraise` | 1.6 min | 5 |
| `perception_test__launching_something` | 1.0 min | 3 |
| `charades__someone_is_cooking_something` | 1.0 min | 2 |
| `repcount__jumpjack` | 0.8 min | 3 |
| **`long_run_all.mp4`** | **81.6 min** | **73 goals armed at once** |

```bash
# the 73-goal long-horizon state run (SPENDS MONEY — has a hard call cap)
set -a; . .env; set +a
PERCEPT_VISION_BACKEND=gemini PERCEPT_VISION_MODEL=gemini-3.1-flash-lite \
  python3 eval/stage-validation/long_run.py --max-provider-calls 2000
```

**`long_run_all.mp4` at 81.6 min is the longest source Percept has ever been evaluated on.**

**Proves:** re-arm, episode continuity across gaps, entity-track and judge-allocation behaviour under
concurrent goals.
**Never proves:** anything about a real 24/7 stream. A concatenated source has a hard cut every ≤90 s,
so scene identity never persists — no lighting drift, no diurnal cycle, no stable background, and no
disconnects.

## L3 — injected long-horizon source

**119.97 min · 32 injected events · 19 distinct watches · 128 labelled intervals (541.5 s).** Clips
with known labels spliced into a long background at seeded offsets, giving **frame-exact ground truth
at a horizon nobody can hand-label**.

```bash
PYTHONPATH=. python3 eval/longhorizon/build_injected_source.py \
  --source-id inject_2h_v1 --target-s 7200 --n-inject 32 \
  --policy jittered --min-gap-s 45 --lead-in-s 60 --seed 20260731 \
  --background-dataset proactiveqa,omnipro \
  --gt-strengths annotated_interval --jobs 6

# verify manifest ↔ media (19 checks incl. decoded frame at every injection offset)
PYTHONPATH=. python3 eval/longhorizon/build_injected_source.py \
  --verify eval/longhorizon/sources/inject_2h_v1.manifest.json \
  --verify-origins --verify-deep
```

| | |
|---|---|
| media | `eval/longhorizon/sources/inject_2h_v1.mp4` — 204 MB, 640×360, 15 fps, CRF 28, no audio |
| manifest | `…/inject_2h_v1.manifest.json` — 104 KB |
| structure | 89 segments (57 background); 825 s injected, 6,373 s **unlabelled** background |
| spread | first event @200 s, last @7107 s; inter-event gap median 195 s, max 313 s |
| honesty | 0 collisions, 0 positives dropped, 1 clipped, max schedule drift 2.0 s |
| licence | **`redistributable: false`** — AND over every contributor incl. background |

**Determinism confirmed empirically** — two independent full rebuilds produced an identical media
sha256. `--require-redistributable` refuses to write at all when any contributor is non-clearable.

Ground truth is tier-pure here (**all 128 intervals `annotated_interval`**), and the manifest keys
watches on `(goal_text, gt_strength)` so a scorer *structurally cannot* merge tiers. Background
segments carry `gt: "none"` — **unlabelled, not negative**.

**Proves:** re-arm across a 2-hour horizon with minutes of idle between occurrences; episode-window
and refractory behaviour past any short clip; recall and latency against frame-exact GT at that
horizon; and every label-free invariant (RSS, ledger reconciliation, restart continuity, judge calls
and cost per source-hour).

**Never proves — and these are active limitations, not gaps:**

- **Not continuous footage.** A hard cut at each of 89 segment boundaries, including within the
  background. No lighting drift, no diurnal cycle, no IR cutover.
- **Scene identity is broken by construction.** Camera, room, people and framing change at every cut,
  so long-horizon re-identification and entity-track longevity are *actively defeated*, not merely
  unmeasured.
- **No precision, no false-positive rate, no F1.** Background is unlabelled, so a fire outside an
  injected interval is **not** evidence of a false positive. The manifest flags 7 goals by lexical
  overlap where that risk is highest.
- **No wall clock**, so `anchor_semantics: "none"` — schedule-derived ground truth (sunrise, transit,
  timed lighting) is invalid on this source. No audio.

This is what you build *because* you have not recorded 72 hours yet — and keep afterwards, because it
stays the only frame-exact ground truth at that horizon.

## L4 — trust / gate cases

**48 scenes, 205 gate cases, 65 labels.** Labels tracked; pixels git-ignored (third-party YouTube,
not redistributable).

> ⚠️ **Not currently trustworthy as a metric.** 180/205 gate cases and 31/48 labels are

## Live sources (for capture, not yet a fixture)

`open_source()` now takes HLS/DASH live streams, which is the prerequisite for recording a
long-horizon corpus from a real camera. **No live fixture exists yet** — this is the capture path
only.

```python
from percept.runtime.source import open_source

# HLS / DASH — live-edge start, retryable open, reconnect with backoff
async for env in open_source("https://cam.example/stream.m3u8", fps=2.0, reconnects=1000):
    ...

# platform-hosted page URL — needs `pip install yt-dlp`, else a clear SourceConfigurationError
async for env in open_source("ytdlp:https://…/live", fps=2.0, live=True):
    ...
```

New knobs: `live=` (force classification for an endpoint whose URI doesn't advertise it),
`retry_open`, `reconnect_backoff_max_s`, `ffmpeg_options`, `ytdlp_format`.

**The media-clock rule — why it matters for latency numbers.** A live stream has no trustworthy
media clock, and previously an `https://…m3u8` fell through the scheme check and had
`CAP_PROP_POS_MSEC` treated as source-timestamp provenance, which flows into latency math. Now:

| URI | live? | media clock |
|---|---|---|
| `https://…/stream.m3u8`, `…/manifest.mpd` | yes | **none** — sliding window, t=0 is meaningless |
| `https://…/video.mp4` | no | **kept** — a progressive file over HTTP has a real clock |
| `rtsp://`, `rtp://`, `udp://` | — | none (unchanged) |

**Test status, stated honestly:** the 4 source suites pass (**119 passed, 51 subtests**) and the
git-index guard passes (**234 passed**). A full-suite run showed 1 failure in
`test_no_card_ids.py::test_public_tree_scope_is_the_git_index`, which **passes in isolation** — a
concurrent session was mutating the git index during the run, and that guard reads the index. A
clean full-suite run on a quiet machine has not been obtained.

## Gotchas that have cost time

1. **Never quote a test count without naming the runner.** `unittest` and `pytest` disagree
   structurally — pytest expands parametrized cases and subtests, so its total is far higher for the
   same code. Compare against *your own branch before your change*, never a number in a doc.
2. **Skip guards must be `unittest.SkipTest` raised at module scope.** `pytest.importorskip` raises
   pytest's own `Skipped`, which unittest's loader turns into a **collection error** — a guard that
   silently only ever worked under one runner.
3. **Do not source the repo-root `.env` for test runs.** A leaked `.env` in `os.environ` produces
   failures that CI never sees.
4. **A new file in the tracked tree must be `git add`-ed** or a repo guard test fails spuriously — it
   reads the git index, not the working tree.
5. **Precision without ground-truth coverage is not a result.** A corpus where most frames are the
   event hands any detector a high score. Publish coverage alongside, always.
6. **Corpus selection bias.** Every clip in `corpus.json` was chosen *because* it contains a labelled
   event. Admission and candidate rates measured on it are upper bounds, structurally
   unrepresentative of a camera that is idle for hours.
7. **More than one Claude session may be writing to this repo.** A guard test that reads the git
   index (`test_no_card_ids.py`) will fail spuriously if another session stages a file mid-run, and
   a full suite can time out competing for CPU. Check `git status` and `git log` before concluding
   you broke something — and before assuming an uncommitted change is yours.
