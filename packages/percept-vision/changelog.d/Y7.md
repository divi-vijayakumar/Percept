### Added — episode state consistency + intervals that do not forward-fill (card Y7)

Foundation for the `percept.episodes` cluster. Two client-viability fixes, both additive; an
un-authored concern is byte-for-byte unchanged.

**State consistency — one authoritative writer.** `EpisodeLog.transition(episode, status, *, t)` is
now the *only* path allowed to mutate `status`/`t_end`, so the pair cannot drift:

* entering a terminal status stamps `t_end = t` (the close time); leaving one (a reopen) clears it.
  `t_end` is therefore derivable — `t_end is not None` iff the status is terminal.
* `t_end` (the episode's END) is distinct from `last_seen` (the last observation). A duration is
  never `last_seen - started_at`.
* `Episode.value` and `Episode.incident_id` use `None` — never `''` — as their one absence sentinel;
  `EpisodeLog.annotate` normalizes an empty string back to `None` so "no value" and "the empty
  string" can never be confused.

**Intervals must not silently forward-fill.** `interval_coverage(observations, *,
observation_valid_for_s=None)` builds coverage from *observed spans or a validity horizon*, never by
joining the dots. An observation at `t` is valid through `min(next_observation, t +
observation_valid_for_s)`:

* two sparse observations (t=1 and t=20, nothing between) are two point observations and one
  **`unobserved`** gap — not a 19-second interval;
* a densely observed run merges into one span;
* a judge-degraded stretch is a **`judge_degraded`** gap, never continued truth and never a confident
  negative.

`observed_total_s` counts span time only. New public surface: `Observation`, `CoverageSpan`,
`CoverageGap`, `Coverage`, `interval_coverage`. The default horizon (`None`) forward-fills nothing.
Behaviour is driven straight off the `eval/synthetic/intervals` corpus (the spec).
