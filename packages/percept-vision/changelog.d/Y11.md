### Added — SHADOW MODE: emit the subject + proposed fold, change nothing, MEASURE (card Y11)

The de-risking gate. Cards Y2–Y15 are all contract/model — NOTHING governs behaviour yet, and Y11
keeps it that way: it only OBSERVES what the model WOULD do. It resolves the subject (Y5 `SubjectRef`)
and recomputes the `EpisodeFoldResult` (Y3 — identity + continuation + Y2 mutation classification) and
EMITS both as ADVISORY data, into the trace AND onto the incident. It does NOT re-arm, NOT suppress,
NOT alter what fires. A consumer that ignores the advisory sees byte-for-byte today's behaviour; the
untraced hot path does no shadow work at all.

- **`percept.behavior.ShadowObservation`** — the pure `(subject, fold)` projection, computed from the
  same side-effect-free `episode_fold`. `to_advisory()` / `from_advisory()` are its JSON-safe
  round-trip pair (all scalars). **`BehaviorExecutor.shadow_observe(...)`** reads the emission ledger
  but never records into it and never touches the gate, so it is safe to run in pure shadow.
- **The trace carries it (a founder handoff depends on this).** New `percept.tracing.STAGE_SHADOW_FOLD`
  (`"shadow.fold"`) in the stage vocabulary, RETAINED AT EVERY LEVEL (it is low-volume — one record
  per subject/fold decision, not per frame). The resolved subject and the fold (match / mutation /
  should_rearm / should_evaluate_gate / supersedes) land IN the `TraceRecord` and survive a media-OFF
  `.ptrace` round-trip (D8b) — a test writes a trace, reloads via `load_trace` and via `TraceBundle`,
  and asserts the subject + fold come back byte-identical. A client can run the wheel on THEIR data
  and hand back a gradeable `.ptrace` with media OFF.
- **On the incident, ADVISORY.** `make_incident(..., shadow=)` attaches the advisory as a runtime-local
  annotation (private attr, exactly like Y10's revision link) read via `incidents.incident_shadow`; the
  WIRE `Incident` shape stays frozen — no schema bump, no webhook-payload change.
- **Live emission.** `agent.perceive_judged` emits `shadow.fold` alongside `gate.classified` — computed
  AFTER the gate already classified, governing no firing — only when a tracer is attached.
- **The per-probe REPORT** (`percept.eval.shadow_report`, driven by `ScriptedJudge` + the committed
  `eval/synthetic` generators, no API spend, no gitignored tree required):
  - **probe 01** (`subject_identity` + `continuation`) — would the proposed identity + continuation
    matching have been RIGHT? A FALSE-BIND is a wrong/fabricated key or collapsing two distinct
    episodes into one (silent merge).
  - **probe 02** (`mutation`) — would the proposed mutation fold (assert/replace/retract) have moved
    the authoritative value correctly? A FALSE-BIND is applying a change the fixture forbids (a
    mention/negation/attribution folded as a replace, or an unauthorized replace).
  Both fold their per-item outcomes through the E-1 metric set (Y8), so the hard false-bind ceiling and
  the weighted harm score (a false bind costs 25x a miss) gate the shadow read. On SYNTHETIC ground
  truth the mechanism proposes the right fold on both probes (match 1.0, zero false binds).

**Honesty (stated, not implied).** This proves the MECHANISM would/would-not have been right on
SYNTHETIC ground truth with the keys/acts already classified. It does NOT prove real-world accuracy —
whether a real OCR/VLM reads a key or a real model classifies a speech act is a benchmark question the
report deliberately does not touch. A disagreement between the fold and a fixture is a DESIGN QUESTION
surfaced, never conformed to.

**Surfaced (not reconciled):** Y4's open question — `distinct_subject_count` counts a lone unknown
sighting as 1 in the fixture but 0 in the E-1 `IdentityLedger` oracle. The report touches the metric
using ONE definition (the fixture's) and FLAGS the other, leaving the reconciliation to the
identity-ledger owner.

The gate is mechanically unchanged; `watch.py` / `WATCH_VERSION` are frozen; defaults are additive.
