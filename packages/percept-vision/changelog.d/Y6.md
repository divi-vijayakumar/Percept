### Added — identity-resolver choice belongs to the CONCERN, not only the source profile

`SourceProfile.identity_strategy` was too coarse as the PRIMARY selector of a subject resolver. One
screen source legitimately carries a document content-key for a purchase-order goal, a track handle
for a cursor / physical-object goal, and NO subject for a global workflow-state goal; one
conversation carries claim-slot, speaker-specific and session-wide goals. The source class cannot
know which a given goal wants — only the goal does.

Resolver selection is now **concern-then-profile**, the same authored-`goal.state` channel every
other concern-level knob uses (`percept.episodes.episode_policy_of`):

- **`percept.identity_policy.select_identity_policy(goal, source_profile)`** returns
  `goal.state['identity_policy']` when the concern declared one, otherwise
  `source_profile.default_identity_policy`. The concern wins.
- **`percept.identity_policy.identity_policy_of(goal)`** reads a concern's declared policy (or
  `None`). Blank / non-string / missing is "declared nothing".
- **`SourceProfile.default_identity_policy`** — a property equal to `identity_strategy`, renaming it
  for what it now is: a DECLARED default/capability the concern may override, not a mandate. Added to
  `SourceProfile.to_dict()`.

Purely additive: a concern that authors nothing inherits the profile default, which for every shipped
profile is its existing `identity_strategy` — unselected behaviour is byte-for-byte today's.

**Envelope (coordinate with the implementation / ADR-007 `security_person_id`).** Making selection per-concern
is also what stops a future biometric resolver from becoming globally active merely because the source
is a security camera: a profile default is a capability a concern may decline, never a global mandate.
`select_identity_policy` re-applies the person-identity refusal at SELECTION time — it raises
`EnvelopeViolation` for any policy that resolves to a person-identifying resolver, the same refusal
`SubjectResolverRegistry.register` makes at registration time, so naming such a resolver in a profile
default cannot switch it on.

`percept.watch()`'s signature and `WATCH_VERSION` are untouched; runtime worker wiring is deliberately
a separate follow-on change (ADR-005 open question 1). Tests: `tests/test_identity_policy.py`.
