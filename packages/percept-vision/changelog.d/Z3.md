### Added — enrich the judgment envelope (reason · watchplan_id · roi · modality · provenance)

Two paying client teams ran domain probes against percept 0.7.0 and both returned *not-viable* — not
because perception failed (their judges scored recall 1.00 and handled retractions, counterfactuals and
speaker attribution correctly) but because the SDK was **unobservable**: of the reference judgment
envelope only ~5 of 11 fields reached a delivered `Incident`. The reason a fire was taken or withheld,
the plan it ran under, and the region/modality/provenance of the evidence all existed internally yet
none crossed the emission boundary. A client debugging percept at 2am saw a bare fire.

Z3 carries them, **all additive, all defaulted, GATE-IRRELEVANT** — a consumer that ignores the new
fields sees byte-for-byte today's `Incident`, and the gate still reads only `satisfied`/`confidence`.
Contract bumped `1.5.0 → 1.6.0` (minor: additive optional fields).

- **`JudgmentEvent`** (the frozen ADR-001 §1 envelope) and **`Incident`** (the delivered record) each
  gain `reason` / `watchplan_id` / `roi` / `modality` / `provenance`, appended LAST so every existing
  positional/keyword construction keeps its meaning.
- **`reason`** — the gate's own O2 `GateReason` (`rising_edge` / `dwell_satisfied` / `low_confidence` /
  `stale` / …). It EXISTED on `GateOutcome` but only ever reached the health/trace channel; the executor
  now reads it off `Gate.decide()` (which *is* the implementation of `evaluate()`, so the firing trace
  is byte-for-byte unchanged) and stamps it on the wire.
- **`modality`** — the `EvidenceModality` the judgment was perceived under (`vision`/`audio`/`fused`),
  taken from the concern's `PerceptionSpec`. **`provenance`** — `observed` vs `inferred`; a judged read
  is a direct `observed` observation.
- **`roi`** — the region the judgment fired on, WHEN known. Left `None` **honestly**: the judge does not
  report the region it fired on today, and echoing the `WatchCondition.region_hint` INPUT would
  misreport an input as an output. The field is plumbed so a future judge that DOES report it can fill it.
- **`watchplan_id`** — a stable id of the plan the judgment ran under (a `PlanIdentity.plan_hash`, card
  X3), which existed in doctor/eval but never on the wire. The per-goal executor does not know the whole
  plan, so it leaves this `None`; `make_incident(..., watchplan_id=…)` lets the runtime that owns the
  goal set stamp it on the delivered `Incident`.
- JSON schema regenerated; the JS edge twin (`percept-edge/src/contract.js` `makeIncident`/
  `parseIncident`) mirrors every new field with closed-vocab validation for `modality`/`provenance`.

`percept/watch.py` and `WATCH_VERSION` are untouched (frozen); all work is behind the existing seams.
