### Added — episode persistence is session-only, now ENFORCED and OBSERVABLE

Episode/counting memory does not survive a restart (the ratified v1.4 decision, ADR-006 / the implementation):
`Percept.snapshot()` carries goals/gate/entities/action_log and deliberately NOT the `episodes` map,
so after a redeploy every counting goal restarts at zero. That was documented but SILENT — the named
Y9 failure mode is an operator under-counting after a restart with nothing saying why. This card makes
the decision hold in code, without changing what fires (additive).

- **`restore()` now emits a loud `episode_memory_reset` health event.** When a restart rehydrates
  active counting goals (`state['type'] == 'count'`) into an empty episode map, `Percept.restore()`
  queues one `RuntimeHealthEvent("episode_memory_reset")` carrying `counting_goals`, `goal_ids` and a
  human-readable `detail`. `percept.runtime.run` drains it into `on_health` exactly once, right after
  `load_state` at startup — the same queue-here / drain-in-worker pattern the judge/gate health logs
  use (Percept never calls `on_health` itself). An operator now SEES the amnesia instead of debugging a
  wrong count at 2am.
- **A tripwire test on `snapshot()`.** `tests/test_z2_episode_persistence.py` asserts `episodes` stays
  out of the snapshot dict. A future accidental add fails the test and forces the session-only policy to
  be revisited deliberately (a persisted representation + a doc rewrite), not flipped by accident.
- **A clearly-marked forward seam: `Episode.to_dict` / `Episode.from_dict`.** Present so a later phase
  can turn persistence ON without reshaping the type — but NOT wired for v1.4 (snapshot/restore never
  call them). The seam is safe because every `Episode` field is an identifier or a STREAM-TIME instant
  (`started_at` / `last_seen` rebase cleanly like a snapshot's deadlines, unlike a wall-vs-monotonic
  `_dwell_since` base with no recoverable duration after a reboot).

Default (no persistence / `restore=False`) is byte-for-byte: the health channel stays quiet and no new
per-tick work runs.
