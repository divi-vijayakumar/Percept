### Added — episode continuation is three decisions, not one

`percept.episodes` now evaluates **subject**, **continuation** and **mutation** as separate
decisions. Exact subject equality is *necessary evidence* for continuation, never its definition —
the same subject (a PO, a person, a door, a claim slot) can legitimately produce several episodes:

```python
continues = (same_subject
             and episode.status == "open"          # ...or the policy allows a reopen
             and observation.ts - episode.last_seen <= continuity_gap_s
             and mutation_is_compatible)
```

* **`EpisodePolicy`** — concern-level continuation semantics (`continuity_gap_s`, `allow_reopen`,
  `terminal_statuses`). A document-presence episode, a door-open interval and a conversational claim
  do not share them, so this is per concern, not a global constant. Three presets ship in
  `EPISODE_POLICIES`; a concern authors one via `goal.state["episode"]`
  (`percept.behavior.coerce_authored_episode`), resolved by `percept.episodes.episode_policy_of`.
* **`ContinuationDecision`** — the typed result of `EpisodeLog.observe_decision()` (and
  `Percept.count_event_decision()`): `subject_matched`, `is_new`, and a `reason` from the closed
  `CONTINUATION_REASONS` vocabulary (`continued`, `reopened`, `new_subject`, `gap_exceeded`,
  `episode_terminal`, `mutation_incompatible`). A refused continuation is logged
  (`episode.continuation_denied`) and metered (`episode.denied.<reason>`) — never silent.
* **`EpisodeLog.close(...)`** gives an episode a lifecycle, which is what `terminal_statuses` reads.
* **Seams** for the follow-on cards, defined but not yet filled: `subject_key=` (the judge-emitted
  subject key, cards Y5/Z3 — passing it already short-circuits the judge) and `MutationCheck`
  (`(episode, exemplar) -> bool` owns the channel).

### Changed

* `Episode` gains `status`, `subject_key` and `observations`; `Episode.representative` is now
  **updated on every continuation** (it was set once at open and never touched — a dead field).
  `exemplar` remains the observation that opened the episode.
* `BehaviorExecutor.fire_episode(..., episode_id=...)` re-arms the per-goal episode key on episode
  **identity** rather than on the count `n`, which a windowed prune could leave unchanged across a
  genuinely different episode. Omitting it keeps the previous `n` discriminator byte-for-byte.
* **`percept/gate.py` is mechanically unchanged.** Episode state reaches the gate only as a
  `rearm()` call from the executor.

Defaults are unchanged: an un-authored concern gets `EpisodePolicy()` (unbounded gap, no reopen), so
existing counting goals behave exactly as before.
