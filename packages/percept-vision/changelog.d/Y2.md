### Added — claim-mode: a value DIFFERENCE is not a REPLACEMENT (card Y2, contract 1.5.0)

Two paying client teams returned percept 0.7.0 *not-viable* despite recall 1.00 — the SDK gave the
executor no safe way to turn a stream of value-bearing findings into one authoritative value, so it
was left parsing values out of free-text `evidence` (unstable, vendor-dependent) with no way to tell
a value that merely APPEARS ("Could we do $25K?") from one that is ASSERTED ("The budget is $40K")
from one that REPLACES ("Actually, the approved budget is $25K"). Four of the five decisive utterances
contain `$25K`; exactly ONE changes the value. Y2 lands the speech-act / mutation channel that fixes
this. Additive and GATE-IRRELEVANT: `watch.py` and `WATCH_VERSION` are FROZEN; the gate still reads
only `satisfied`/`confidence`, so a verdict that sets none of these reproduces today's firing
byte-for-byte. Contract semver `1.4.0` → `1.5.0` on both edges.

- **`Verdict` claim-mode fields** (`percept.contracts`, appended last, all defaulted): `operation`
  (the LOCAL speech act — `assert`/`confirm`/`replace`/`retract`/`close`/`mention`), `value`,
  `normalized_value`, `target_revision_id`, `asserted_by`. The judge classifies the act from the
  CURRENT turn ALONE — the prior value never enters the satisfaction prompt, which preserves the
  anchoring mitigation ("actually it is $25K" is classifiable locally). Default `operation="assert"`
  with `value=None` is a no-op on any slot, so a plain positive verdict is unchanged.
- **`Operation` / `OPERATIONS` / `MUTATING_OPERATIONS`** vocabularies. Only `replace`/`retract`/`close`
  are mutating; `assert`/`confirm`/`mention` are not. `assert` ESTABLISHES an empty slot but never
  overwrites — overwriting an established value is exactly what `replace` is, and `replace` is gated.
- **`percept.claims`** — the claim state machine that folds the channel into one authoritative value.
  `ClaimState` / `apply_operation` / `fold_verdicts` implement: containing a value is not asserting it
  (a question, an attribution and a negation all leave the value UNCHANGED); a valueless `retract`
  clears a value to `None` (never `""`); a `replace` supersedes and names the revision it superseded.
  Every step returns a typed, explainable `ClaimOutcome`.
- **`ConcernAuthority` + `Concern.authority`** — authority is a property of the CONCERN, evaluated
  SEPARATELY from the speech act. A well-formed `replace` from an asserter the concern does not
  authorize (a seller against a buyer-authoritative budget) is DOWNGRADED to a non-mutating mention —
  the value does not move — and the downgrade is TRACED (`claim.authority_downgrade`), never silent.
  `authority=None` (default) is unrestricted, byte-for-byte today.
- **Episode-fold wiring** — `percept.behavior.episode_mutation_of(operation)` maps the speech act to
  the Y3 `EpisodeFoldResult.mutation` vocabulary (`replace`→`updated`, `retract`→`retracted`,
  `close`→`closed`; the rest → `confirmed`). `BehaviorExecutor.fold_episode(..., operation=)` threads
  a verdict's operation straight into idempotency with no value parsing; omitting it is unchanged.
- **JS twin + schema** — `percept-edge/src/contract.js` `_makeVerdict` carries the five claim fields
  when present (a pre-1.5 verdict keeps its exact `{satisfied, confidence, evidence}` shape) and
  rejects an out-of-vocabulary `operation`. JSON schema regenerated (`Verdict` gains the fields;
  `ConcernAuthority.schema.json` added).
- **Fixtures are the spec** — the `mutation` synthetic corpus (`eval/synthetic/mutation/`) is now
  *consumed*, not just validated: the five-utterance case (`value_after` = $40K,$40K,$40K,$40K,$25K),
  the valueless retraction (→ `None`), and the seller-replace-blocked-by-authority case ($40K stands).
