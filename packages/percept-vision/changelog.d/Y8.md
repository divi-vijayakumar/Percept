### Added — E-1 identity-metric building blocks + a non-inferiority engine

Eval-layer machinery for grading identity/episode behaviour offline. All additive; nothing here runs
in the watch runtime or changes what fires.

**E-1 identity metrics** (`percept.eval.identity_metrics`): `classify_binding`, `compute_e1_metrics`
and the supporting rates (`normalized_key_collision_rate`, `cross_run_consistency`). A **false bind**
(two distinct subjects merged) is scored as strictly worse than an abstention/miss — the asymmetry that
keeps a report from looking "green" by binding everything.

**Deterministic reference oracle** (`percept.eval.identity_ledger.IdentityLedger`): a seeded, model-free
ground-truth ledger of sightings/bindings that an SDK run can be compared against, so identity accuracy
is measured against a fixed reference rather than a moving model.

**Non-inferiority engine** (`percept.eval.noninferiority`): `NonInferiorityResult`, `required_n_for_margin`,
`norm_ppf`, bootstrap lower-bound — a predeclared-margin verdict that can return **UNDERPOWERED** when the
sample is too small to conclude.

**Scope — what this change does NOT do (read before relying on it):** these modules are building blocks,
**not a wired quality gate**. Nothing in the runtime, the shipped CLIs, or the test suite currently
computes a non-inferiority verdict or compares a run to the `IdentityLedger` on any automatic path;
`percept.eval.shadow_report` uses the metric helpers, but no A/B regression is gated by them yet. Wiring
these into an E-1..E-4 regression check is future work. This change also does **not** add property-based
(`hypothesis`) tests; the eval layer is covered by example-based tests only.
