### Added — envelope enforcement in config, not prose (card Z7, ADR-007)

The seven-domain evaluation returned OUT for three domains. Those refusals lived only in prose, and
prose does not stop a client wiring something. They are now typed config:

- **`percept.envelope`** — the three OUT verdicts as data (`OUT_OF_ENVELOPE`), each carrying its
  reason, its *narrowed survivor* and the exact boundary between them, plus how much of it is
  machine-enforced (`structural` / `declared` / `docs`).
- **No person-identifying resolver ships, and one cannot be constructed.** `SubjectResolver` refuses
  at construction to derive a person key from pixels, or to persist a person key percept derived;
  `SubjectResolverRegistry.register` re-checks independently. The four shipped resolvers
  (`track_iou_label`, `appearance_recent_set`, `content_key`, `speaker_label`) mirror ADR-005's
  `identity_strategy` values and identify nobody. A client's own identity enters through
  `client_asserted_subject(value=..., asserted_by=...)` as a `binding='bound'` key — `bound` is
  reachable only from `derives_from='client_asserted'`. percept never derives person identity from
  pixels.
- **`ConsentProfile.actuation`** (`"none"` | `"screen"` | `"physical"`) — the typed declaration, in
  the ADR-005 `UNTUNED` style. Declaring `"physical"` makes `permits()` refuse every action and
  `Percept.act` raise quoting the verdict, because the gate's honest failure mode is ASK and a
  control loop cannot ask. Reachable from deployment config via `ConsentSettings.actuation` /
  `PERCEPT_ACTUATION`.
- **`percept doctor` says it** — a new ENVELOPE panel and `envelope` block in `--json`, the
  `--actuation` flag, findings `OUT_OF_ENVELOPE_ACTUATION` and `PERSON_IDENTIFYING_RESOLVER`, and a
  new exit code **6** (`EXIT_OUT_OF_ENVELOPE`).

Reported honestly rather than overclaimed: **"assistant-class delivery only" is enforced in DOCS,
not in config.** `AttentionPolicy` clamps interrupt *authority*, never consumer *class* —
`AttentionIntent.preferred_channel` is free text, so a sink driving a horn is indistinguishable from
one that speaks. `ATTENTION_CLASS_ENFORCEMENT` and `ATTENTION_CLASS_GAP` record that, and ADR-007 §4
names the three additive pieces that would change it.

Every existing configuration is unchanged (`actuation` defaults to `"none"`); `percept/watch.py` and
`WATCH_VERSION` are untouched.
