### Added — revision coalescing; a 24/7 confirm heartbeat is no longer an unbounded log (card Y15)

Second stress-test defect (found by the seven-domain eval, not either domain probe). A long-running
watch confirms the SAME finding on every confident tick — a heartbeat — and the naive episode timeline
appended a `Revision` per confirmation. Over a 24/7 watch that is an **unbounded log**: N identical
confirmations become N rows, forever. A re-statement of an unchanged fact is not a state change and
must not grow the timeline.

`percept/episodes.py` now gives each `Episode` a **bounded revision timeline** with one coalescing
writer:

* **`Revision`** `{kind, t, value, incident_id}` over the closed `REVISION_KINDS`
  (`opened` · `confirmed` · `updated` · `retracted` · `closed` · `expired` · `unobserved_gap`).
* **`EpisodeLog.record_revision(episode, kind, *, t, …)`** — the single choke point. A `confirmed`
  heartbeat **COALESCES IN PLACE**: it advances `last_confirmed` / `last_seen` (never backwards) and
  appends **nothing**. A run of N unchanged confirmations therefore produces exactly **one** row — the
  `opened` that began the episode. Only the state-changing kinds
  (`STATE_CHANGING_REVISION_KINDS` = everything except `confirmed`) append.
* An unchanged same-subject **continuation** records `confirmed` (no row); a **reopen** records
  `opened`; `EpisodeLog.close(...)` records `closed`. `Episode` gains `last_confirmed` and `revisions`.
* The timeline is **capped** at `max_revisions` (drop-oldest) with a **traced** drop —
  `on_revision_drop(episode, revision)` when wired, else an `episode.revision_dropped` log line —
  matching the ADR-001 §9 drop discipline `EpisodeLog` already applies to `max_episodes`. Because
  confirmations coalesce, no volume of heartbeats can approach the cap.

**Invariant (pinned by `tests/test_y15_revision_coalescing.py`, the `eval/synthetic/idempotency/`
spec):** an unchanged re-confirmation emits no new incident and the episode's revision count does
**not** grow with confirm ticks.
