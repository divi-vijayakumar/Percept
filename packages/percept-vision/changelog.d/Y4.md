### Added — `unknown` subject: operational semantics in the episode fold

The `SubjectRef` contract collapsed the three absence representations into **two** — `SubjectRef.resolution ∈ {bound,
unknown}` — and made the episode LOG's default honest: `_subject_key_of` returns `None` for an
`unknown` ref, so the log mints a fresh episode per unidentified sighting and **two unknowns never
collapse** (they are NaN-like — never equal, not even to themselves). This change does **not**
re-litigate that; it lands only the fold's gate governance and the opt-in single-focus
attach — and answers four explicit design questions:

* **Mint / attach.** An `unknown` mints a fresh episode by default (the existing behaviour) and
  never matches another unknown — so a visible abstention cannot fabricate shared identity.
* **Rearm — no.** `percept.behavior.episode_fold(..., unknown=True)` now returns the new first-class
  `match="unknown"` with `should_rearm=False`, `should_evaluate_gate=True`. Even though the subject
  resolver minted an episode for the unknown (which the legacy fold would read as `new` and **re-arm**), a visible
  abstention must never re-arm an edge a bound subject already spoke on — that would be exactly the
  wrong suppression this board exists to kill. It degrades to gate-only like `unbound`, but keeps its
  **own observable state** so a client debugging at 2am can tell *seen-but-unidentified* from *no
  subject at all*. It is also never granted episode-owned idempotency (two unknowns are never the same
  episode), so the emission ledger is not consulted on this path.
* **Continue a bound episode — only under an explicit opt-in.** New
  `EpisodePolicy.unknown_attaches_to_active_bound` (default `False`): a narrowly single-focus source
  MAY provisionally continue the **sole** open bound episode with an unknown sighting when no boundary
  event intervened (open, inside the continuity gap, exactly one thing in focus). The attach is
  RECORDED — a distinct `ContinuationReason` `"unknown_provisional_continuation"` and a `confirmed`
  revision — never a silent merge. With two open bound episodes the sighting could belong to either, so
  it refuses to guess and stays unbound.
* **Merge on later bind — no silent merge.** Because an unknown carries no key it can never be adopted
  by a later bound sighting: an `unknown` then a `bound` subject mints **two** episodes
  (`subject_matched=False` on the bound one). A merge across already-minted episodes would require an
  explicit resolver decision recorded in the trace, which is outside this change's default scope. The
  single-focus opt-in avoids the duplicate up front instead: the bound subject's return continues the
  very episode the unknown rode.

Scope note: this completes the dependencies for advisory shadow mode. The gate is mechanically
unchanged — `unknown` reaches it only via the fold's `should_rearm` /
`should_evaluate_gate`, under the episode-fold contract — and `watch.py` /
`WATCH_VERSION` and all defaults are frozen. Additive: `subject_is_unknown()` is the single
discriminator (`percept.episodes`), `EPISODE_MATCHES` gains `"unknown"`, and legacy callers (no
`unknown=` argument, opt-in off) are byte-for-byte unchanged.

Surfaced disagreement (not conformed to): `eval/synthetic/subject_identity` case
`unreadable_key_binds_unknown` expects `distinct_subject_count: 1` for a single unknown sighting,
whereas the E-1 oracle `percept.eval.identity_ledger.IdentityLedger` deliberately keeps `unknown`
sightings OUT of `distinct_subject_count` (tracking them in a separate `unknown_count`, never firing).
Those are two different definitions of "distinct subject" (does an unidentified sighting count as a
subject at all?). This is a genuine design question in the eval/oracle layer, outside the fold, and is
left for the identity-ledger owner rather than silently reconciled here.
